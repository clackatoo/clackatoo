```
clackatoo [--font <FAMILY>] [--font-size <POINTS>] [--renderer <API>] [--remote <HOST> | --connect-picker]
clackatoo <COMMAND> [OPTIONS]
```

With no command, `clackatoo` opens [the window](~clackatoo/reference/window), starting the daemon first if none is running. With `--remote`, the daemon is [on another machine](~clackatoo/reference/remote). With `--connect-picker`, the window first asks which machine, from those you've connected to, your ssh config and Tailscale (see [picking a machine](~clackatoo/reference/remote#picking-a-machine)).

On failure, every command prints `clackatoo: <what went wrong>` to stderr and exits with status 1.

## daemon

```
clackatoo daemon [--scrollback-compaction <WHEN>] [--fresh]
```

Runs the daemon in the foreground until interrupted. Its log goes to stderr, at the level `RUST_LOG` sets (default `info`). Terminals live exactly as long as the daemon does: when it stops, their programs are hung up. [Upgrading](#upgrade) it doesn't stop it. Ctrl+C, closing the terminal it runs in, or SIGTERM stop it the way [stop](#stop) does; under `nohup` it outlives a hang-up, upgrades included. The programs in its terminals take those signals as usual, however the daemon was started.

`CLACKATOO_AGENT` gives Claude Code, the agent [chats](~clackatoo/reference/agents) talk to unless told otherwise, another command: one speaking ACP, split at spaces.

`CLACKATOO_UDP_PORTS` sets the UDP ports connections from other machines may [move onto](~clackatoo/reference/remote#moving-onto-udp): a port, a range such as `60000-61000` (the default), or `off`.

`CLACKATOO_LSP_TRACE` names a file every message to and from [language servers](~clackatoo/reference/editor#language-servers) is added to, a line each: the time in UTC, the server and its pid, then `->` for what it's sent, `<-` for what it sends, or `!!` for a line it wrote to stderr. Only you can read the file it makes, and it must be a plain file.

`CLACKATOO_ACP_TRACE` names a directory every message to and from each agent [chats](~clackatoo/reference/agents) talk to is written to, in the same form, a file for each agent the daemon starts, with obvious secrets taken out (see [tracing agents](~clackatoo/development/tracing-agents)).

`CLACKATOO_DISPLAY=off` leaves the programs the daemon starts with its own `WAYLAND_DISPLAY`, `DISPLAY` and the like, rather than [the desktop's display](~clackatoo/reference/terminal-emulation#the-display) as you log in and out, which they follow by default.

`CLACKATOO_WORKSPACES` names the file the daemon keeps its workspaces in, or `off` to keep none. By default it's `workspaces` in `$XDG_STATE_HOME/clackatoo/` (or `~/.local/state/clackatoo/`).

The daemon keeps your workspaces, tabs and panes in that file as they change, about a second after each change, and once more as it stops or upgrades. A daemon starting afresh makes them again (see [the window](~clackatoo/reference/window#after-a-restart)); an upgrade doesn't need to. A file that can't be read, or is from a newer clackatoo, is renamed `workspaces.unreadable`, and the daemon starts with none. Each file read is copied to `workspaces.previous`, so panes that couldn't be made, as on a disk not mounted, aren't lost. Only one daemon keeps the file at a time (it locks `.workspaces.lock`); another keeps nothing.

| Option | |
|---|---|
| `--scrollback-compaction <WHEN>` | When scrollback is compacted to save memory: `lazy` (the default), `eager` or `off`. See [scrollback](~clackatoo/reference/terminal-emulation). |
| `--fresh` | Start with no workspaces this once, rather than making again those kept from the last run. The file is left as it is until something changes. |

The daemon keeps its files in a per-user **runtime directory**: `$XDG_RUNTIME_DIR/clackatoo/`, or `/tmp/clackatoo-<uid>/` if `XDG_RUNTIME_DIR` is unset.

| File | |
|---|---|
| `daemon.sock` | The Unix socket clients connect to. |
| `daemon.lock` | Locked while a daemon runs, so only one runs at a time. A second `clackatoo daemon` fails with "a clackatoo daemon is already running". |
| `shell/` | The scripts that make shells [mark their commands](~clackatoo/reference/window#commands), written by the daemon when it starts, and `display`, the [desktop's display](~clackatoo/reference/terminal-emulation#the-display) shells follow, written whenever it changes. |

Anyone who can connect to the socket can run commands as you, so the directory must be accessible only by you. The daemon creates it with mode `0700`, and refuses to start if it exists with any group or other permissions, or belongs to someone else.

Unix socket paths are limited to about 100 bytes. A very long `XDG_RUNTIME_DIR` makes the daemon fail with "path must be shorter than SUN_LEN".

A daemon the window starts runs in the background, with its log in `daemon.log` in the runtime directory.

## upgrade

```
clackatoo upgrade
```

Moves the running daemon onto this build of clackatoo without stopping it. Its terminals, the programs in them, their history and the workspaces all carry on, and so do agents, with all they run and the turns they're answering, unless the upgrade has to stop them (see [Agents](~clackatoo/reference/agents#through-an-upgrade)). Run it after building or installing a new clackatoo.

The daemon replaces its own program with this one, keeping its process, so the programs in its terminals stay its children. It hands its state over as it goes: everything on screen and in history, the cursor and modes, workspaces and tabs. Every connection drops for a moment. Windows on this machine reconnect by themselves; windows on other machines say the connection was lost, and Enter reconnects them. Recordings stop.

Before handing anything over, the daemon checks that the new program is a clackatoo that can take over from it. If it isn't, or starting it fails, the daemon carries on as it was, and `upgrade` says why; the daemon's log has the details. A daemon won't upgrade to a build speaking an older protocol; one speaking the same, such as the build before, it will. Daemons from before protocol 11 can't upgrade at all: `upgrade` says so, and `clackatoo stop` is the way to replace them, closing their terminals.

## update

    clackatoo update [--check] [--channel <CHANNEL>] [--to <VERSION>] [--rollback]

Installs the latest release of clackatoo in place of this one, then moves the running daemon onto it, as [upgrade](#upgrade) does. Releases come from [github.com/clackatoo/clackatoo](https://github.com/clackatoo/clackatoo/releases). Each has its checksums signed with clackatoo's release key, whose public half every build carries, and nothing is installed unless the signature is that key's, it names the release being installed, and the download is what the checksums say.

The new build is written beside the old one, run once to be sure it works on this machine, then renamed over it, so the program is never missing or half written. The old one is kept beside it as `clackatoo.previous`. Windows already open keep the old build until they're opened again.

| Option | |
|---|---|
| `--check` | Only say whether there's a newer release. |
| `--channel <CHANNEL>` | `stable` (the default). `nightly` isn't published yet. |
| `--to <VERSION>` | Install this version, newer or older, instead of the latest. |
| `--rollback` | Swap back to the build the last update replaced, and move the daemon onto it if it can. Run again, it goes forward again. |

Versions are `YEAR.MONTH.N`: `2026.10.0` is October 2026's first release, `2026.10.3` its fourth. `clackatoo --version` also says the commit and the day it was built.

The first release to install, before there's a clackatoo to update with, is installed by hand, checking its signature first: the [README](https://github.com/clackatoo/clackatoo#install) shows how.

## desktop

    clackatoo desktop install [--force]
    clackatoo desktop remove [--force]

Puts clackatoo in your desktop's app launcher, with its icon, or takes it out. `install` writes `clackatoo.desktop` to `~/.local/share/applications` and the icon to `~/.local/share/icons/hicolor/scalable/apps` (under `$XDG_DATA_HOME` if it's set). The entry starts the program `install` was run as, by its full path, so run it as the clackatoo you want the launcher to start. Docks group clackatoo's windows under it.

The entry tells the launcher that clackatoo reports its startup, so a window opened from the launcher takes focus as it opens and the launcher's spinner stops. The token the launcher hands the window goes no further: the daemon and your shells never see it. An entry written by an earlier clackatoo gains this the next time [update](#update) rewrites it.

The entry's right-click menu offers a new window; "Connect to…", which opens the window as the [picker of a machine](~clackatoo/reference/remote#picking-a-machine); and "Connect to HOST" for each of the last three machines you connected to. When the machines you've connected to recently change, the window rewrites a marked entry to list them, still starting the program the entry started. If a pinned launcher keeps showing the old menu, GNOME has a copy of the entry cached: unpin clackatoo and pin it again, or log out and back in.

Both files are marked as clackatoo's (`X-Clackatoo-Managed=true` in the entry). An entry or icon without the mark is yours: `install` leaves it as it is and prints the entry it would have written, and `remove` leaves it too. `--force` replaces or removes it anyway. To keep your own changes to an entry clackatoo wrote, delete its `X-Clackatoo-Managed` line.

[update](#update) brings a marked entry and icon up to date with the build it installs, and leaves unmarked ones alone. The README's install runs `desktop install` too.

## forget

```
clackatoo forget HOST
```

Forgets the identity key the daemon knows the machine of its connection HOST by, in `known_machines`, after that machine's clackatoo chose a new one, as when its `machine` file was deleted: the key it shows next is taken, and kept. Until then, a connection to it is refused, and says so. See [machines passed on](~clackatoo/reference/remote#machines-passed-on).

## lent

```
clackatoo lent
clackatoo lent reclaim N
```

Lists the panes this daemon has [lent to another machine](~clackatoo/reference/remote#a-pane-on-another-machine), numbered, with the machine each is lent to and when it was last heard from. `reclaim N` takes one back: it becomes one of this daemon's own workspaces, named after the machine it was lent to, as `from-laptop`.

## display

```
clackatoo display
```

Shows the desktop's display the daemon on this machine gives the programs it starts, and where it came from, then each variable as `NAME=VALUE`:

```
from: systemd (the desktop you're logged in to)
WAYLAND_DISPLAY=wayland-0
DISPLAY=:0
XAUTHORITY=/run/user/1000/.mutter-Xwaylandauth.Q2ZXV3
XDG_SESSION_TYPE=wayland
XDG_CURRENT_DESKTOP=ubuntu:GNOME
```

`from:` is `systemd` while you're logged in to the desktop, `inherited` for the daemon's own display, or `none`. A variable not listed is removed from what the daemon starts. See [the desktop's display](~clackatoo/reference/terminal-emulation#the-display) for where each comes from. It reads what the daemon wrote for its shells, so it fails, saying so, while no daemon is running, or the daemon hasn't written it: `CLACKATOO_DISPLAY` is `off`, it hasn't read the display yet, or it couldn't write the file, which its log says. A file an earlier daemon left is passed over. It shows this machine's daemon only: for another machine's, run it there, as `ssh desk clackatoo display`.

## stop

```
clackatoo stop
```

Stops the daemon, closing every terminal and hanging up their programs. The daemon is sent SIGTERM and stops as it would at logout or shutdown: it tells its language servers to shut down, ends what agents started, writes the boards' last changes, writes the workspaces as they were, and tells windows on other machines why, all within about 3 seconds. One that hasn't gone after 5 seconds is killed; a daemon from before 2026.10.17 dies at once. `stop` works on a daemon from any build of clackatoo, which matters because a build refuses to talk to a daemon speaking another version of the protocol: other commands then fail with "the daemon is from another version of clackatoo", and suggest `clackatoo upgrade` where the daemon can upgrade. If no daemon is running, `stop` says so and succeeds.

## config

```
clackatoo config [<NAME> [<VALUE>]] [--unset <NAME>]
```

Shows or changes the window's [settings](~clackatoo/reference/window#settings) in `client/startup.toml`:

- With no arguments, prints every setting as the file would hold it, with those the file doesn't set commented out at their defaults.
- With a name, prints that setting's value, without quotes, so scripts can use it.
- With a name and a value, sets it. The value is checked first: `clackatoo config renderer metal` fails, saying which values `renderer` takes.
- With `--unset`, removes the setting, so it takes its default.

Changes keep the rest of the file, comments included, as it was, and the file is replaced all at once, so a window starting at the same moment reads either the old file or the new one.

## language

```
clackatoo language list
clackatoo language install <NAME>... | --all [--no-servers]
```

The languages files are [parsed and coloured](~clackatoo/reference/editor#languages) in. Each is a pack in `~/.local/share/clackatoo/languages` (or `$XDG_DATA_HOME/clackatoo/languages`).

- `list` lists the languages clackatoo knows where to get, with where each comes from, marking those installed and naming each one's [language server](~clackatoo/reference/editor#language-servers), then any other packs installed.
- `install` downloads each language's grammar and highlight queries, with curl, from the grammar's own repository, at the version clackatoo was tried with, and checks each file is exactly what was tried. Then it installs the language's server, unless it's on `PATH`, `--no-servers` is given, or clackatoo can't install it (it says how to). `--all` installs every language `list` lists. Installing one again replaces it, and a language once declined in a window is offered again.

Files opened after a language is installed are parsed in it. A file that was already open is parsed once a window attaches to it again, as when the window is next opened.

## bridge

```
clackatoo bridge [--replace]
```

Passes everything on its standard input to the daemon, and everything the daemon sends to its standard output, starting the daemon first if none is running. It exits when either side hangs up. `--remote` runs it on the other machine through ssh; see [another machine](~clackatoo/reference/remote).

| Option | |
|---|---|
| `--replace` | Replace the daemon that's running first, as when it's from another build: [upgrade](#upgrade) it if it can, keeping its terminals, or else stop it, closing them. |

## Client commands

The other commands talk to a running daemon. Each accepts:

| Option | |
|---|---|
| `--socket <PATH>` | Connect to this socket instead of the one in your runtime directory. |
| `--remote <HOST>` | Use the daemon on another machine (`host`, `user@host`, `host:port`, or a name from your ssh config), through ssh, starting it there if it isn't running. See [another machine](~clackatoo/reference/remote). |
| `--remote-command <COMMAND>` | With `--remote`, the command that runs clackatoo there. Default: `clackatoo`, or `CLACKATOO_REMOTE_COMMAND`. |

Terminals are named by the number `new` prints and `list` shows. Numbers are never reused while the daemon runs.

### list

```
clackatoo list
```

One line per terminal: its ID, the PID of its program (`-` for a [chat](~clackatoo/reference/agents), which has none), its size, its status (`running`, `exited (<code>)` or `killed (signal <n>)`), and the window title its program set.

### new

```
clackatoo new [--size <COLSxROWS>] [--cwd <DIR>] [--record <FILE>] [-- <COMMAND>...]
```

Starts a terminal and prints its ID.

| Option | |
|---|---|
| `--size <COLSxROWS>` | The terminal's size, like `120x40`. Default `80x24`. Each dimension must be between 1 and 4096. |
| `--cwd <DIR>` | The working directory. Default: the current directory. |
| `--record <FILE>` | Write everything the program prints to `FILE`, as a [recording](~clackatoo/reference/recordings). The path is on the daemon's machine. |
| `-- <COMMAND>...` | The program to run, and its arguments. Default: the daemon's `$SHELL`, or `/bin/sh`. A `$SHELL` that starts another shell rather than becoming it, as `sh -c fish` does, gets nothing typed into it by clackatoo (see [keeping a terminal running](~clackatoo/reference/window#keeping-a-terminal-running)): set it to the real shell. |

What a program sees in its environment is described in [terminal emulation](~clackatoo/reference/terminal-emulation).

### bg

```
clackatoo bg [--workspace <NAME>] [--cwd <DIR>] [--size <COLSxROWS>] -- <COMMAND>...
```

Starts the command, its words joined with spaces, in a new [background tab](~clackatoo/reference/window#background-tabs) of a workspace, and prints its terminal's ID, for `capture` and the rest. It's typed at a new shell's prompt, as you would type it, so the shell's marks say when it runs and how it ends, and it shows in the window's list of background tabs, out of the tab bar. A workspace from another machine can't have one started yet.

| Option | |
|---|---|
| `--workspace <NAME>` | The workspace, by its name. Default: the one last used. |
| `--cwd <DIR>` | The directory the shell starts in. Default: the current directory. |
| `--size <COLSxROWS>` | The terminal's size, like `120x40`. Default `80x24`. |

### keep

```
clackatoo keep <TERMINAL> [restore|always|off]
```

Marks the terminal to [keep running](~clackatoo/reference/window#keeping-a-terminal-running) the command its shell runs, or ran last, as its shell said: `restore`, the default, runs it again by itself as the daemon starts afresh; `always` also runs it again as it ends; `off` takes the mark away. It says what it keeps running, or why it can't, as when the shell hasn't said what it ran.

### edit

```
clackatoo edit [PATH]
```

[Edits the file](~clackatoo/reference/editor) at `PATH`, or shows the [folder's listing](~clackatoo/reference/editor#folders), from the current directory, which is the folder shown if there's no `PATH`, in a new tab of the workspace last used, or in a new workspace if there are none. A file already being edited gets another pane on it. The window doesn't switch to the new tab yet.

### run

```
clackatoo run <TERMINAL> <WORDS>...
```

Types the words, joined with spaces, into the terminal, then presses Enter (a carriage return, `\r`).

### send

```
clackatoo send <TERMINAL> <TEXT>
```

Types `TEXT` exactly as given, without pressing Enter. To send control keys, use your shell's escapes: `\e` (Escape) or `\r` (Enter) in fish, `$'\e'` in bash. Fails if the terminal's program has exited.

### capture

```
clackatoo capture <TERMINAL> [--ansi]
```

Prints what the terminal is showing: one line per row, without trailing spaces or trailing blank lines. With `--ansi`, colours and attributes are kept as escape sequences, so printing the result in another terminal reproduces the screen. A terminal whose program has exited still shows its last screen.

### resize

```
clackatoo resize <TERMINAL> <COLSxROWS>
```

Changes the terminal's size, such as `clackatoo resize 1 120x40`. Its program is told (the kernel sends it `SIGWINCH`), and lines on the screen are rewrapped to the new width. A recording started with `new --record` stops here, because a recording has a single size.

### close

```
clackatoo close <TERMINAL>
```

Closes the terminal and forgets it. Its program is hung up (sent `SIGHUP` by the kernel), as when a terminal window closes.

### ping

```
clackatoo ping [--count <N>] [--interval <MS>]
```

Times how long the daemon takes to answer, and how long a key takes to come back from a program, which is most useful with `--remote`. It starts a terminal of its own running `cat`, and for each round:

1. waits, then times a request that does nothing, which is what the connection costs;
2. waits again, then times a key, from sending it to the update that shows `cat`'s echo, which is what typing costs.

With `--remote`, each round also says whether it went [over UDP or through ssh](~clackatoo/reference/remote#moving-onto-udp). To the same machine, where the network costs next to nothing:

```
$ clackatoo ping --remote localhost --count 5
connected to localhost in 146.1 ms
PING localhost: a request, then a key echoed by cat
round 1: request 0.168 ms, key echo 0.216 ms (over UDP)
round 2: request 0.147 ms, key echo 0.226 ms (over UDP)
round 3: request 0.158 ms, key echo 0.187 ms (over UDP)
round 4: request 0.147 ms, key echo 0.187 ms (over UDP)
round 5: request 0.151 ms, key echo 0.178 ms (over UDP)

--- localhost ping statistics ---
request   min 0.147 ms, median 0.151 ms, p90 0.168 ms, max 0.168 ms
key echo  min 0.178 ms, median 0.187 ms, p90 0.226 ms, max 0.226 ms
```

The connection time includes ssh logging in. When it's done, ping closes its terminal.

| Option | |
|---|---|
| `-c`, `--count <N>` | How many rounds. Default: 10. |
| `-i`, `--interval <MS>` | The wait before each request and each key, in milliseconds. Default: 200. The first message after a pause is the slowest, because whatever carries it has to wake up, and typing always has pauses, so a short interval flatters the result. |

`--soak` keeps the connection open until Ctrl+C, typing into a terminal every `-i` milliseconds, and logs each echo's time and every drop, reconnect and its reason: for watching a bad network over hours.
